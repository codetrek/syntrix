# CEL Evaluator

## Overview

The CEL (Common Expression Language) evaluator matches trigger conditions against
Syntrix document change events. Its input follows the business event produced by
Puller transformation, including logical document deletion.

## Interface

```go
// Evaluator evaluates trigger conditions against events.
type Evaluator interface {
    // Evaluate returns true if the trigger condition matches the event.
    Evaluate(ctx context.Context, trigger *types.Trigger, event events.SyntrixChangeEvent) (bool, error)
}
```

## Condition Syntax

Trigger conditions are CEL expressions over the `event` object:

```yaml
triggers:
  - triggerId: "notify-on-shipped-order"
    database: "myapp"
    collection: "orders/*"
    events: ["update"]
    condition: 'event.document.status == "shipped"'
    url: "https://webhook.example.com/orders"
```

## Event Context

| Field | Type | Description |
|----------|------|-------------|
| `event.type` | string | Business event type: `create`, `update`, or `delete` |
| `event.timestamp` | integer | Puller normalization timestamp in Unix milliseconds |
| `event.document` | map or null | Flattened current `Document.Data`, with stored `id`, `collection`, and `version` added; a logical delete has only these metadata fields |
| `event.before` | map or null | Flattened previous document if supplied to the evaluator; always `null` on the current production Puller path |

The evaluator declares one CEL variable, `event`. Document metadata overwrites
business fields with the same names. `event.document.id` is the stored document
identifier, not a guarantee that the original business ID is available. Raw
update descriptions are not exposed in this CEL context.

## Document Deletion and Before Images

A Syntrix logical delete is a MongoDB update that retains a tombstone with
`deleted=true`, business `data={}`, and document metadata. Transformation maps
an update or replacement carrying that tombstone to business `delete` and keeps
the tombstone in `Document`. Consequently, `event.document` is a metadata map
for this event, not `null`, and fields such as `balance` and `status` are absent.
The `deleted` storage flag itself is not added to the CEL map; use
`event.type == "delete"` to identify the event.

MongoDB physical document deletes are excluded from business evaluation through
`ErrDeleteOPIgnored`. Later physical removal of a tombstone does not fire a
second deletion trigger. See the [storage deletion contract](../../core/storage/03.stores.md#document-deletion-and-physical-cleanup).

The current normalizer, buffered event, and transformation do not carry a
previous image. `event.before` is therefore `null` for create, update, and
logical delete events on the production Puller path. Setting `includeBefore`
does not supply missing data. A condition such as
`event.before.balance > 0` cannot inspect the deleted document's prior balance.

[Capture Trigger Before Images](../../../../../.agents/notes/proposed/feature/2026-09-07-trigger-before-images.md)
remains a proposal. It owns source pre-image capture, retention, transport,
rule-level exposure, and unavailable-image failures. Conditions that compare
old and new values require that capability; evaluator support for an explicitly
supplied `Before` value alone does not provide it.

## Collection Matching

The `collection` field supports glob patterns via `path.Match`:

```yaml
# Match specific collection
collection: "users/profiles"

# Match all subcollections
collection: "orders/*"

# Match nested paths
collection: "tenants/*/users"
```

## Examples

### New Document Created

```cel
event.type == "create" && event.document.type == "premium"
```

### Updated Document State

```cel
event.type == "update" && event.document.status == "shipped"
```

This checks the current status, not whether the status field changed.

### Logical Document Deletion

```cel
event.type == "delete" && event.document.collection == "accounts"
```

### Complex Condition

```cel
event.type == "update" &&
event.document.status == "approved" &&
event.document.amount > 1000
```

## Caching

CEL programs are compiled once and cached:

```go
type celEvaluator struct {
    env      *cel.Env
    programs sync.Map  // triggerID -> cel.Program
}
```

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Invalid CEL syntax | Error at trigger load time |
| Runtime evaluation error | Log error, skip trigger (no match) |
| Missing field or null before-image access | Evaluation error; use `has(...)` or an explicit null guard when absence is expected |
| Non-boolean condition result | Evaluation error; the condition must return a boolean |
